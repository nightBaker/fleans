# Adding a new BPMN activity

Use this guide when the new behavior is a first-class BPMN concept (gateway, event, structural activity). For plugin-shaped behavior (REST call, email, custom external system) use [Adding a custom-task plugin](./adding-a-custom-task-plugin.md) instead.

## Steps

1. Create the activity class in `Fleans.Domain/Activities/` — extend the existing `Activity` base class.
2. Register it in `Fleans.Infrastructure/Bpmn/BpmnConverter.cs` so BPMN XML maps to it.
   If it carries a condition or script, add it to `Fleans.Application/Deployments/WorkflowExpressionValidator.cs` so a deploy compiles it (#975).
3. Add tests in `Fleans.Domain.Tests/` using Orleans `TestCluster`. **Every activity must have tests that verify workflow state after both completion and failure** — see `ScriptTaskTests.cs` and `TaskActivityTests.cs` for the pattern:
   - **Completion tests:** completed activities list, variable merging (count + values), activity instance marked completed, no active activities remain, sequential chaining.
   - **Fail tests:** error state set with correct code/message (500 for generic Exception, 400 for BadRequestActivityException), failed activity does **not** transition to its outgoing flows (`WorkflowExecution.ResolveTransitions` skips failed and cancelled entries — an error boundary catches it; otherwise the workflow fails once nothing else is active), no variables merged on failure.
4. Update the BPMN elements table in `README.md`.
5. Add a manual test plan under `tests/manual/NN-<name>/` and append it to `tests/manual/README.md` (canonical catalog).
6. Add a website docs page or update an existing one under `website/src/content/docs/`.

## Adding a script language

A new `scriptFormat` is not a new activity: it stays a `ScriptTask`. Implement `IScriptEngine` (`Fleans.Application.Abstractions/Scripts/`) — its `Formats`, `Execute` and `Compile` — and register it with `services.TryAddEnumerable(ServiceDescriptor.Singleton<IScriptEngine, MyEngine>())` next to the built-in ones in `AddInfrastructure`. `ScriptExpressionExecutor` routes by format (case-insensitive) and throws at startup when two engines claim one format. Register on every silo that deploys or runs scripts: deploy validation (`WorkflowExpressionValidator`, Core) and `ScriptExecutorGrain` (Worker) both resolve engines by format, and the parser accepts any format, so an unregistered one is rejected at deploy (#1070).

Built in: `DynamicExpressoScriptEngine` (`csharp`, `c#`, empty) and `JavaScriptScriptEngine` (`javascript`, `js`; Jint; variables cross as JSON and only top-level keys whose JSON changed — compared with the input as JavaScript round-trips it — are written back, so untouched values keep their .NET type). `PythonScriptEngine` (`python`, `py`; IronPython 3.4, #1102) uses the same JSON round trip with `_context` as a `dict`; it has no stdlib (imports allow-listed), per-run builtins and module copies, and `PythonScriptPolicy` rejects dunder and frame/traceback attribute names at compile (syntax-tree walk) and in `getattr`/`setattr`/`delattr`/`hasattr` — without it `e.__traceback__.tb_frame.f_builtins` reaches `clr`. It enforces its timeout and a stack budget from IronPython's trace hook on a dedicated 16 MB-stack thread — a hook that raises on every line past the limit, so `except:` cannot swallow it, and a byte budget because IronPython drops its recursion check on functions that throw often. A single builtin call fires no trace event, so the caller is also released with a `TimeoutException` 2 s after the timeout (the thread runs on) and runs are capped at `Environment.ProcessorCount`. No memory limit. Errors leave the engine as plain `InvalidOperationException`/`TimeoutException`, since IronPython exceptions carry Python objects Orleans cannot serialize to the instance grain. The parser dedents Python scripts instead of trimming them (`BpmnConverter.Dedent`). The parser rewrites the `${var}` shorthand for C# formats only (`BpmnConverter.IsCSharpScriptFormat`), since in JavaScript it is template-literal syntax. Each engine should stop a runaway script itself rather than only time the caller out (Jint and the Python engine do; DynamicExpresso cannot).
